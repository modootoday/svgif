# Implementation plan

## Goal

Ship svgif.js as static browser files: SVG-only rendering, three backends from one IR, a 3D bake, and Studio at `/studio/` on GitHub Pages. The final definition of done is three tiers at once. A release is not a fourth shortcut. [[sot:svgif/release-gate]]

## Release timing

Recorded in [[adr:svgif/20261110122100]] and `.github/RELEASING.md`.

1. Now: a maintainer publishes the placeholder `@modootoday/svgif@0.0.0-stage` by hand so the trusted publisher can be attached. That is not a `v*` tag and not a GitHub Release. Role: `release`.
2. The repository is public, which is what npm provenance requires. `v0.1.0` still waits for the gates below. It is not cut early because the repository is already public.
3. `v0.1.0` is created by the release workflow only after Milestone 0, the sensitive-content gate (`SVGIF_REQUIRE_DENY_TERMS=true`), and every tier below are green on that same commit. Docs, chore, ci, test, refactor, and style commits never select a version. Role: `release` dispatches; every other role does not.

## Docs delivery order

Role: `docs`. Build one Pages artifact, and verify URLs in this order, stopping at the first failure.

| Priority | Path | Work package |
| --- | --- | --- |
| P0 | `/` marketing landing. The first action is Open Studio. | `WP-DOCS-P0` |
| P1 | `/studio/` | `WP-DOCS-P1` (placeholder, then the M8 app) |
| P2 | `/guide/` user guide | `WP-DOCS-P2` |
| P3 | `/developers/` API, schema, embedding, contributing | `WP-DOCS-P3` |

`WP-DOCS-P0` can run beside M0. P1's scaffold follows P0. The live app replacement is M8 and stays priority P1 for the site. P2 follows the P1 scaffold. P3 follows P2. Schema reference text waits until M0 has frozen the files.

## Steps

1. M0, `WP-SCHEMA`. Freeze `schema/project`, `schema/ir`, `schema/exporter-job`, and `schema/backend-result` at v1. Role: `schema`. Critical path starts here.
2. Parallel after M0: `WP-MATH` and `WP-IR` (`scene`, `animation`). Then `WP-CLOCK`, `WP-CSS`, `WP-SMIL`, `WP-CAP`, `WP-LOW` on the animation lane, and `WP-SCENE`, `WP-MESH`, `WP-PROJ`, `WP-SHADE` on the scene lane. They join at `WP-BAKE`.
3. `WP-PLAY`, then exporters `WP-HTML`, `WP-SVG`, `WP-WEBP`, `WP-WEBM`, `WP-MP4` (GIF stays optional and is not a release row).
4. `WP-STUDIO` for load, save, preview, copy-source, and the in-file relay.
5. M8 copies the Studio build onto Pages at `/studio/` and checks `data-svgif-studio="app"`.
6. Tier 2 infrastructure stays green the whole way. Tier 3 evidence is collected on the release SHA. The release workflow tags only then.
7. `WP-AGENT` (M9) starts after `WP-SCHEMA`, `WP-IR`, and `WP-SVG`. It does not sit on the Studio critical path. The release manifest still requires its rows. Role: `agent`.
8. `WP-EMBED` (M10) starts after `WP-HTML`, `WP-WEBP`, and `WP-MP4`. It does not sit on the Studio critical path. The release manifest still requires `oembed-json`, `social-card`, and `embed-player`. Role: `export`, with `schema` for `schema/embed/` and `studio` for the Save control.

## Critical path

`WP-SCHEMA` → `WP-MATH` → `WP-SCENE` → `WP-MESH` → `WP-PROJ` → `WP-SHADE` → `WP-BAKE` → `WP-PLAY` → `WP-MP4` → `WP-STUDIO` → `WP-DOCS-P1` live app → tier-3 manifest → `v0.1.0`.

The animation lane (`WP-IR` → `WP-CLOCK` → CSS and SMIL → `WP-LOW`) joins at `WP-BAKE` and is not a reason to tag early. `WP-AGENT` joins the manifest after SVG export exists. It does not delay `WP-STUDIO`. `WP-EMBED` joins the manifest after HTML, WebP, and MP4 exist. It does not delay `WP-STUDIO`.

| Preset authoring | Frame 0 is the true start state, with nothing revealed unless the type says otherwise. That frame-0 state is visible in the SVG markup with the CSS removed. Geometric motion defaults to non-linear easing. The motion is visible at native size: travel is meaningful, and a change of about 2px is not the motion. A mask or a clip reveals content that differs from its own shape. Tempo matches the declared bpm. A beat uses a fast-attack ease-out and a slower decay. Growth scales from its anchor, the baseline or the inner radius. Non-text graphics have at least 3:1 contrast against their background. A preset-authoring assignment cites these rules | [[sot:svgif/preset-registry]] | `studio` |

## Tier 3 — end-to-end

The matrix is `schema/release-readiness/scenarios.v1.json`. Evidence is a Playwright run on the deployed Pages site and on a pasted embed, for Chromium, Firefox, and WebKit. Each pair needs a first-attempt pass, an evidence file (report, and a screenshot or video under the artifact), and the checks in the release-gate table: file signatures, dimensions, frame counts, durations, playable media, the relay, migration, both embeds, offline playback, and no project-server requests.

The run's `retryCount` is 0. A job that was rerun does not count. The artifact's commit is the release SHA. Spec check and the CI gates on that SHA are `passed`.

Roles match the table in [[sot:svgif/release-gate]]. The release role assembles the manifest and does not edit a failed row into `passed`.

From the deployed site, once `SVGIF_CDN_BASE` is set, the exact-version URL returns 200 with the immutable Cache-Control, the content type, and the sha384. The alias URL uses `max-age=300` and the embed snippet has no SRI on it. [[adr:svgif/20261110164419]]

## Final definition of done

All three tiers pass on one commit, and `mode=release` is the command that creates the tag. A green merge is not done. Studio live at `/studio/` is necessary and not sufficient without the manifest.
