# Release timing and the scoped package name

## Context

`@modootoday/svgif` is not on npm yet (registry 404 on 2026-11-10). npm Trusted Publishing can be attached only to a package that already exists. `@modootoday/specfold` used a one-time `0.0.0-stage` version for that claim; that version is on the registry ahead of `0.2.0`. The unscoped name `svgif` is already taken by an unrelated package created on 2021-12-10 (latest `0.1.0`). Provenance attestations are issued only when the GitHub repository is public. This repository is public.

## Decision

1. **Name claim now.** A maintainer publishes `@modootoday/svgif@0.0.0-stage` once, by hand, from a logged-in npm session. The tarball is a placeholder: it names the package, carries the license, and says it is not the engine. CI does not publish `0.0.0-stage`. After that version exists, the Trusted Publisher is attached (organization `modootoday`, repository `svgif`, workflow `release.yml`, environment `npm`). Any later package under `@modootoday/` gets the same one-time placeholder before its own publisher is attached.
2. **First real release waits.** The repository is already public, which is what npm provenance requires. Milestone 0 (`node scripts/ci/check-schema.mjs`) and a green sensitive-content job (including a set `SVGIF_DENY_TERMS` secret) are necessary and not sufficient. No `v*` tag is created until [[sot:svgif/release-gate]] is satisfied for that exact commit, including the full end-to-end scenario matrix. The first product tag is `v0.1.0`, created by the release workflow, and published with `--provenance`.
3. **Always the scoped name.** Docs, README, and CDN examples call the package `@modootoday/svgif`. They do not tell anyone to install the unscoped name `svgif`. The IIFE global stays `svgif`. That global is not the npm name.

## Consequences

The stage tarball can sit on npm while the schema is still being frozen. It must not be documented as a usable library, and it is not a GitHub Release. `v0.1.0` cannot ship from a private repository if provenance is required. Visibility changes first; the release workflow then creates the tag only after the release gate passes. A doc page that writes `npm install svgif` is a failed package-name check.
