After H-017 is `done` and merged, record the rules and the job. Each rule below has a check that fails when the rule is removed or contradicted.

URL scheme, in [[sot:svgif/distribution]]:

- Exact version: `/svgif/<x.y.z>/...`. Written once. `Cache-Control: public, max-age=31536000, immutable`. SRI is required for the JS and CSS objects. `integrity.json` for that version is immutable and lives on this prefix.
- Aliases: `/svgif/<major>/` and `/svgif/latest/`. `Cache-Control: public, max-age=300, must-revalidate`. No SRI on these URLs.
- Content types set at upload: `.js` and `.mjs` are `application/javascript; charset=utf-8`, `.css` is `text/css; charset=utf-8`, `.svg` is `image/svg+xml; charset=utf-8`, `.json` is `application/json; charset=utf-8`.
- Upload the raw bytes. Do not set `no-transform`. Edge compression is the zone's job. SRI is over the decoded bytes.
- Required response headers, configured by the owner on the zone and recorded here: `X-Content-Type-Options: nosniff`, `Cross-Origin-Resource-Policy: cross-origin`, `Referrer-Policy: no-referrer-when-downgrade`. Do not put a strict Content-Security-Policy on these responses.
- Bucket CORS, recorded as the owner-applied policy: `GET` and `HEAD`, allowed origins `*`.
- jsDelivr and unpkg may appear only as labeled secondary documentation URLs. They are not the origin for `cdn.thumly.io`.

Cite public docs only: [R2 public buckets](https://developers.cloudflare.com/r2/buckets/public-buckets/), [R2 CORS](https://developers.cloudflare.com/r2/buckets/cors/), [default cache](https://developers.cloudflare.com/cache/concepts/default-cache-behavior/), [purge](https://developers.cloudflare.com/cache/how-to/purge-cache/), [compression](https://developers.cloudflare.com/speed/optimization/content/compression/), [transform rules](https://developers.cloudflare.com/rules/transform/), [jsDelivr SRI](https://www.jsdelivr.com/using-sri-with-dynamic-files). Do not cite an account id, a zone id, or a private page.

`bash scripts/ci/check-release-workflow.sh` fails if the distribution record or `release.yml` contradicts those headers, marks an alias immutable, attaches SRI to `/svgif/latest/` or `/svgif/<major>/`, or names jsDelivr or unpkg as the origin of `cdn.thumly.io`.

Upload job in `.github/workflows/release.yml`, after the gate, Environment `cdn-release`:

1. Build the artifacts for that SHA.
2. Hash those bytes with sha384. Publish `integrity.json` on the exact-version prefix.
3. Dry-run: list the keys and content types. Fail if the exact-version prefix already exists. Do not upload and do not purge.
4. Put only the exact-version prefix. Reject a key that already exists. Use the immutable Cache-Control and the content types above.
5. After that prefix is stored, copy the same bytes to `/svgif/<major>/` and `/svgif/latest/` with the alias Cache-Control. Do not rewrite the exact-version prefix.
6. Purge only the alias URLs. Do not purge the exact-version URLs.
7. Fetch the exact-version URL and compare status, content type, and sha384. Attach that evidence to the GitHub Release.

`mode=check` runs steps 1 through 3 only. With no environment token it stops after the local key plan and still does not call Put or purge. With the token present it may check that the prefix is absent, and it still does not Put or purge. A real prerelease dry-run is this job, not a comment. Rollback rewrites alias keys to the previous version's bytes and purges those URLs. It does not delete an exact-version object.
