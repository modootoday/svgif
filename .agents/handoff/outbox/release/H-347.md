# Handoff H-347

## State

After #589, the "Agent surface tests" job failed on `main` with `SyntaxError: Export 'ExportCapabilityError' is not defined in module`.

CI pins Bun 1.3.14. When Bun 1.3.14 bundles an entry that only re-exports, such as `packages/svgif-export/src/index.ts`, it writes a 305-byte export list and no definitions. Bun 1.4.4 bundles the same entry correctly.

Under 1.3.14 this broke two files:
- `@modootoday/svgif-export`'s `dist/index.js`, the published package entry.
- The CLI's `dist/browser/export.js`.

Every other output of `build-packages.mjs` matched 1.4.4.

## Done

`scripts/ci/build-packages.mjs`:
- An entry that only re-exports is bundled through a temporary wrapper, `export * from "<entry>"`. This covers the export package (`reexports: true`) and the CLI's browser bundle.
- The check refuses any `.js` or `.mjs` file under `dist/` that exports names and declares or imports nothing. On the 305-byte file from 1.3.14 it reports the problem.

`packages/svgif-cli/test/browser.test.ts`: the built-bundle test bundles through the same wrapper.

Checked with Bun 1.3.14 and with Bun 1.4.4:
- `build-packages.mjs --self-test` passes.
- The full build writes `svgif-export/dist/index.js` and `svgif-cli/dist/browser/export.js` at about 138 KB each.
- `test/browser.test.ts` in `packages/svgif-cli` passes, 11 of 11, with Chromium.

## Not done

- Moving the CI pin to a newer Bun. That is a `.github/` change.
