- **Playwright cache.**
  - The CI rehearsal job and `e2e.yml` restore `~/.cache/ms-playwright` with `actions/cache/restore`.
  - They save it with `actions/cache/save` only from `main`.
  - The key is the runner OS, the locked `playwright` version, and the browser set.
  - Chromium is installed with `--only-shell`.
- **setup-node.** The two steps that left its package cache on now set `package-manager-cache: false`.
- **Player bundle.** CI fails when a fresh Studio build changes `apps/studio/src/player-bundle.ts`.
- **Supply-chain check.** `scripts/ci/check_supply_chain.py` fails in these cases:
  - A cache is saved anywhere but `main`.
  - The combined `actions/cache` step is used.
  - A cache is used in `release.yml` or `pages.yml`.
  - `setup-node` keeps its package cache.
  - A build output or an installed tree is tracked.
  - A tracked file is over 1 MiB.
  
  It prints the preset registry's size on each run. Its self-test covers each case.
