## Done

`.github/workflows/release.yml`:
- New `mode=stage`.
  - The gate requires `stage-readiness` from a successful `e2e.yml` run on the commit, checked with `--phase stage`.
  - The version step runs, the `tag` job does not, and the `cdn` job uploads as `mode=release` does.
  - It keeps the exact-version comparison as the artifact `cdn-stage-evidence`.
- **Finding the evidence:** `mode=release` and the `publish` job try each successful `e2e.yml` run on the commit, until one carries `release-readiness`. A stage-only run is never picked.
- **`mode=check`:** when the token listed the bucket and the prefix was absent, it writes `cdn-dry-run.json` and uploads it as the artifact `cdn-dry-run`. The file holds the commit, the version, the prefix, and the key plan.
- **Reusing the staged upload:** when `mode=release` finds the exact-version prefix, it reuses it only if the prefix holds exactly this build's file names and each exact-version URL returns this build's sha384. Then the upload script skips the Put, and the purge and the exact-version verification still run. Any other existing prefix fails, as before. `mode=stage` and `mode=check` still fail on an existing prefix.

`.github/workflows/e2e.yml`:
- The assemble step tries the release manifest, then `--phase stage`.
- `stage-readiness` is uploaded only when no release manifest was written.
- The agent step gets `GH_TOKEN`.

`scripts/e2e/agent.mjs`: the `cdn-dry-run` row is no longer a stub.
- It lists the successful `workflow_dispatch` runs of `release.yml` for the commit and downloads `cdn-dry-run`.
- It checks the mode, the commit, the x.y.z version, the absent prefix, and the key plan.
- Without a token or without such a run, it is `blocked` and names the step that is missing.
