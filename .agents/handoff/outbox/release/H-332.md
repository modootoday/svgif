## Done

The cause is a Firefox behavior that the harness did not handle. Studio is not broken.
- Studio finishes the WebP in Firefox in about 4 seconds and shows "WebP is ready".
- The locked Playwright moved from 1.63.0 to 1.65.0 in #519, and the Firefox build moved with it, to Firefox 159.
- For `<a download>` on an `image/webp` blob, Firefox 159 opens the file in a new tab. Its pref `browser.download.viewableInternally.enabledTypes` includes `webp`. Playwright reports that tab as a new page, not as a download, so the row waits until it times out.
- In the same Firefox, `image/png` and `video/webm` download as usual, and with the pref empty every type downloads.
- The old commit `04cf9f4` fails the same way with Firefox 159, so no Studio commit caused this.

`scripts/e2e/browser.mjs` now launches Firefox with that pref set to an empty list. The other engines launch as before.

Measured locally with Firefox 159 from Playwright 1.65.0, against this checkout's build: Firefox passed 10 rows, failed 0, and blocked 6. The 6 blocked rows need the CDN or `--target site`. `export-webp@firefox` passed.
