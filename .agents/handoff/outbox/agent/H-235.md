# Handoff H-235

## State

Started from `main` at the merge of `modootoday/svgif` pull request 453. The owner set an unattended goal that names the roadmap's measured state as the source of work. The M10 row said `export --browser` returned `internal` and wrote no file.

## Done

`packages/svgif-cli/src/browser.ts` runs the export package in a local headless Chrome or Chromium. It serves only `packages/svgif/src/` and `packages/svgif-export/src/` from a server on 127.0.0.1, strips their TypeScript types with the runtime's own stripper (Node 22.13 or later, or Bun), drives the browser through the DevTools protocol with the runtime's built-in WebSocket, and writes the returned file. It adds no dependency. `SVGIF_BROWSER` picks the binary; otherwise the first Chrome or Chromium on `PATH` is used. No browser is exit 4. A failed encode is exit 70 and writes nothing. `gif` stays exit 70, because the export package has no GIF exporter.

`packages/svgif-cli/test/browser.test.ts` covers the served-path filter, the type stripper, the no-browser exit, and, when a browser is present, the WebP frame count, the WebM EBML header, and the MP4 `ftyp` box or a `codec-unsupported` exit.

In this session, with Chromium, the node bin wrote a 69,884 byte WebP, a WebM, and a 570,329 byte MP4 from `schema/fixtures/project/v1-valid.json`.

## Not done

The skill text in `skills/svgif-export/SKILL.md` and `schema/agent-surface/source.v1.json` still lists `gif` among the browser formats. That source is under `schema/`, which is human-gated.

Firefox and WebKit are not driven by this path; it speaks the Chrome DevTools protocol only.
