# Handoff H-241

## State

Started from `main` after pull request 460. On pull request 457, at merge commit `f6377f8`, the job `Agent surface tests` failed in `packages/svgif-cli/test/browser.test.ts`: the MP4 export, the third browser run in that file, reported `TypeError: Failed to fetch dynamically imported module: http://127.0.0.1:42737/svgif-export/src/index.ts`. The WebP and WebM runs before it in the same job loaded the same modules and passed. It did not reproduce in 13 local runs under Bun or with the node bin.

## Done

The loopback server sends `Connection: close` on every response, so the browser never reuses a socket that the server side may be closing; a reset on a reused socket fails one module fetch and the whole import with it. That is the likely cause, without direct evidence, because the failing run recorded nothing from the server.

The server now records every request it did not serve (404, 405, or a 500 with the type-stripping error). A failed module load is retried once in a new page, because a page keeps a failed fetch in its module map. An encode failure is not retried. When both attempts fail, the error names both browser messages and what the server did not serve.

With `packages/svgif/src/ir/quantize.ts` moved away for one run, the error read: `the export modules did not load twice. First: TypeError: Failed to fetch dynamically imported module: .../svgif-export/src/index.ts Server: 404 /svgif/src/ir/quantize.ts. Second: ...`. The file was restored. After the change the CLI tests passed 5 times in a row under Bun, and the node bin wrote WebP, WebM, and MP4.

## Not done

The cause on the runner is not proven. If the failure returns, its error now carries the server record.
