# Handoff H-287

## State

Started from `main` after H-286. `export --browser in a local browser > webm starts with the EBML header` failed again in CI on pull request 500 with the same message: the export module fetch fails twice in about half a second, and the loopback server reports no request it did not serve. So H-286's `content-length` did not remove it.

## Done

The cause is a race in `waitForPage`. A new target starts on `about:blank`, whose `document.readyState` is already `complete` before the navigation to the export page commits. When the poll lands there, the export script runs on `about:blank`. Its import of `http://127.0.0.1:<port>/svgif-export/src/index.ts` then comes from a null origin, so the browser blocks the cross-origin module fetch. The server serves the request, so it reports no problem. The WebM test runs right after the WebP test with a warm browser, which makes the early poll more likely there.

`waitForPage` now waits for `location.origin` to be the loopback origin as well as a complete document. `pageReadyExpression` holds that check, and a test evaluates it on `about:blank`, a loading page, the export page, and another port. The `content-length` from H-286 stays; its comment no longer claims a cause.

The CLI tests pass (27).

The code change landed on `main` inside the squash of pull request 501: the unattended merge run amended that preset commit in the same working tree while this change was uncommitted. This pull request adds only this record. Pull request 501's preset files are unaffected.
