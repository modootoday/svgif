## Done

`camera-zoom` `scale` scales `attr.d` on `subject-f0`, `subject-f2`, `subject-f4`, `ground-f0`, `ground-f2`, and `ground-f4`, with `at` 1.24. The default factor is 1, so the baked faces stay the same size. A larger scale enlarges those faces about each face's own box center. That matches the zoom: a larger scale enlarges the subject. The stage is not a target. No layer was added.

No other camera parameter has a bind. `scene` stays without one. A render with the zoom bind matches the same preset with the bind removed. Committed goldens were not rewritten.

These parameters stay unbound. A bind has to follow the parameter in direction and magnitude.

- `latitude` and `azimuth` on every camera preset: they are camera angles. Changing one re-projects the baked faces. `scale` resizes the existing outline by the ratio of the two angles. Latitude is negative on these presets, so a larger value shrinks or flips the face. No current kind re-projects a baked face.
- `distance` on every camera preset: moving the camera farther away makes the subject smaller. `scale` with `at` equal to the distance makes the face larger. The size follows the inverse of the distance. No current kind does that.
- `camera-frame` `margin`: a larger framing margin widens the field until the subject sits inside that margin, so the subject gets smaller. `scale` makes the face larger.
- `x` and `y` where they are declared (`camera-cut`, `camera-dolly`, `camera-frame`, `camera-ken-burns`, `camera-orbit` `y` only, `camera-pan`, `camera-parallax`, `camera-zoom`): they are camera position in world units. Without `depthRatio`, the pose reader shifts the eye by `(value - rest) * subjectDepth` along camera right and up. The picture moves opposite that shift. After depth cancels, the screen gain is `height / (2 * tan(fovY / 2))` pixels per unit, not 1. With `depthRatio` the strafe is the translate itself, so the gain still depends on depth and the sign is still opposite. `offset` adds `value - at` pixels with the same sign and no gain. No current kind multiplies that delta by the projected gain. A constant written into the bind would be hand-tuned.
- `camera-cut` `view`: a free string. `near`, `far`, and `wide` are not a declared value list. One swap key list would be written onto every face, and the faces do not share one path.
- `camera-ken-burns` `start`: the value is 0. Retime cannot use 0 as its fixed point, so the default would collapse every key to frame 0. An offset would add 24px, which is not a time remap.
- `camera-ken-burns` `endFrame`: retime doubles the baked key frames, and the pose reader stretches the sample by the same factor, so the probed frames match the default.
- `camera-parallax` `depthRatio`: doubling 0.6 to 1.2 drops `ground-f0` and `ground-f4`. Naming them is a missing node. Leaving them out changes pixels outside the surviving faces. One scale cannot scale the far box and the near slab by different factors.
- `camera-shake` `strength`: the amplitude follows the direction chosen by `seed`. A fixed axis would be that hash. Scaling a face changes its size, not the shake amplitude.
- `camera-shake` `seed`: the value picks a direction. A bind axis is constant, so offset cannot follow a new seed. Swap cannot cover every integer.
- `camera-zoom` `center`: the value is the free point string `160 90`. A one-axis offset is not that point. No partial swap.

The schema package needs three kinds this category cannot express today: an inverse scale (face size follows `at / value`) for `distance` and `margin`, a projected offset (opposite sign, gain taken from the camera math above) for `x` and `y`, and a re-projection of the baked faces for `latitude` and `azimuth`. H-167 is that schema package. It already owns declared values, per-layer variant keys, and a 2D offset for a point such as `center`. This package does not edit the schema.

`--goldens` fails on the first unbound name in each camera file other than the zoom's `scale`, which is bound. `camera-cut` also reports the pre-existing mid-frame band miss. `camera-ken-burns` also reports the pre-existing size cap. `camera-dolly`, `camera-ken-burns`, `camera-orbit`, `camera-pan`, `camera-parallax`, `camera-shake`, and `camera-zoom` also report that the committed golden differs from the generator. That difference was already on `main`. `camera-cut` and `camera-frame` already matched. Those goldens stay byte-identical.
