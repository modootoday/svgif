# Handoff H-249

## State

Started from `main` after pull request 472. Issue 454 recorded that Studio's layer groups were editor state only: a saved file reopened with every node ungrouped, and the Tier 1 row "Composition round-trip" failed. Issue 470 recommends an optional `groups` field at revision 1.

## Done

This package implements that recommendation for the owner to accept or refuse.

- `schema/project/v1.1.schema.json` has an optional closed `groups` list: each group has an `id` of 1 to 64 characters and two or more `childIds`. Revision 0 has no `groups`; `schema/migrate.mjs` asserts both. `check-schema.mjs` validates one valid and four invalid fixtures under `schema/fixtures/migrations/groups/`.
- `packages/svgif-export/src/groups.ts` checks a list against the composition: child ids must be node ids, a group id must not be a node id or repeat, and a node is in at most one group. The HTML writer accepts `groups` only at revision 1 and writes it into the project script.
- Studio writes the groups that still have two or more nodes, at revision 1; with no group and no card it writes revision 0 as before. Opening a file restores the groups through `restoreGroups()`.
- Tests: a grouped composition saves, reopens, and saves again with the same groups and node order; a lone-child group is not saved; a broken group is dropped on open; six invalid group shapes are refused by the writer. Studio passes 62 tests and the export package 66.
- [[sot:svgif/html-project]] states the rule. The Tier 1 audit marks Composition round-trip pass: 33 pass, 2 partial, 0 fail, 5 open.
