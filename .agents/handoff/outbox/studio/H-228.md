# Handoff H-228

## State

Started from `main` after pull request 456. The assignment names two CI failures of `apps/studio/test/sale-task.test.ts` with `browser did not open a debugging port` after the 20000 ms wait. A third failure of the same kind came from the copy of this helper in `packages/svgif/test/smil.test.ts`, in the job `Records, schema, and presets` of run 43822774572 on pull request 449; the same tests passed in `Engine tests` of that run and on the rerun.

## Done

Evidence, measured in this session with Google Chrome for Testing 153.0.8010.12 and a fresh profile per launch:

- A warm launch printed `DevTools listening on ws://127.0.0.1:<port>/` 130 to 152 ms after spawn. Its only other stderr lines were two dbus errors, printed before or with the DevTools line.
- After deleting `/var/cache/fontconfig` (119 fonts), the first launch printed the line after 477 ms and the next after 141 ms. A cold font cache costs time, and it grows with the font count; a hosted runner has far more fonts and shared CPU.
- The CI failures recorded no browser stderr, because the helper dropped it on timeout. The cause of the 20 s stall on the runner therefore has no direct evidence. The named cause is a slow cold start on the runner, longer than 20 s, which this session could not reproduce.

Fix, in both copies of the launch helper:

- Each launch uses a fresh profile, as before.
- The port wait is 60000 ms.
- A failed launch kills the browser, removes its profile, and reports the time waited and the last 4000 characters of browser stderr.
- One relaunch with a new profile follows a failed launch, and it is logged with that report. `studio-shell.sh` also logs the time the port took to open.
- The three browser tests now allow two port waits plus their own work: 180000, 180000, and 210000 ms.

A forced hang proved the path. A stand-in for `google-chrome` that printed one line and slept on its first call made the suite log:

```
browser launch failed; relaunching once with a new profile. browser did not open a debugging port after 60031 ms. Browser stderr:
fake: hang without a DevTools line
```

and the suite then passed, 7 pass and 0 fail.

The Studio suite ran green 10 times in a row locally with the new launch helper, before the test timeouts were raised; the forced-hang run above used the final timeouts:
