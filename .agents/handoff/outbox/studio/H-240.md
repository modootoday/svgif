# Handoff H-240

## State

Started from `main`. H-239 adopts `tsc` for the engine and export packages and names Studio as having no `tsconfig.json`.

## Done

`apps/studio/tsconfig.json` checks `src/` with the DOM and DOM iterable libraries and no `@types` package. `tsc` 5.9.3 reported 17 errors, now 0.

One error was a real bug. `main.ts` names its edit history `history`, which shadows the window's. `persistShell()` called `history.replaceState(...)` on the edit history, so switching the shell on an address with `?mode=` threw after saving the choice and left `?mode=` in the address. It now calls `globalThis.history.replaceState(...)`. `scripts/ci/studio-shell.sh` now asserts that the switch removes `mode` from the address. With a fresh Studio build the new check failed before the fix (`the switch left ?mode in the address: ?width=1440&height=900&mode=advanced`) and passed after it.

The other fixes change types only: `restKey()` declares the `number[]` value it can return, which every caller already rejected; the `MediaRecorder` probe is typed as a constructor, so its narrowing no longer reaches `never`; the import failure code is `Extract<ImportResult, { ok: false }>["code"]`; an SVG element cast goes through `unknown`; and the player document's element type may carry an `id`.

## Not done

The root `typecheck` script does not run Studio yet; that script is in `package.json`, which H-239 changes. The CLI and MCP packages need `@types/node` to check, which is a lockfile change.

## Next

The `release` role adds `apps/studio/tsconfig.json` to the root `typecheck` script after H-239 merges, and decides on `@types/node` for the CLI and MCP packages.
