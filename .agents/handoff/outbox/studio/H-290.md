# Handoff H-290

## State

Started from `main`. Four `later` catalogue types reuse the v1 dataviz and icon looks: `viz.line`, `viz.area`, `viz.progressRing`, and `icon.progressRing`.

## Done

- `viz-line`: axes, three gridlines, and a seven-point line with dots that rises from the baseline.
- `viz-area`: the same axes and grid, an area at 0.4 opacity, and an edge line, rising from the baseline.
- `viz-progress-ring`: a dark track ring and a value arc that sweeps clockwise from 12 o'clock to 72 percent.
- `icon-progress-ring`: the same ring at icon size in `#cc5528`, centred at (160, 90), filling a full turn.

Unlike the v1 dataviz presets, all four pass the strict golden check:

- The line and area use `cubic-bezier(0.4, 0.2, 0.45, 1)`, which puts the mid frame at about 67 percent of the rise.
- The rings start slowly, because a ring's bounding box reaches full height at half a turn.
- Each moving ring arc is a 16-segment polyline whose chord sag stays under 1 unit. `pathBox` in `check-presets.mjs` bounds an `A` command conservatively, by its radii around both end points, so even a zero-length arc measures a full circle's box and the band measure cannot follow an arc sweep.
- Each track ring is dark enough to stay out of the motion metric, so the sweep is the motion it measures.

The files are 2,926 to 11,354 bytes and the goldens 1,938 to 10,304 bytes.

`check-presets.mjs --goldens` on the `dataviz` and `icons` categories reported nothing for these four, and `check-presets.mjs` passes. The 15 v1 dataviz presets on `main` still report the mid-frame band; they predate that rule.

The visual review passed on rasters of frame 0, the mid frame, and the last frame, judged against [[sot:svgif/handoff]].

## Not done
