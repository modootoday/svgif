# Handoff H-245

## State

Started from `main`. H-244 recorded that `export-mp4@firefox` wrote a file Firefox reports as 16 by 160 pixels, and made the scenario runner keep the file. Run 43838624282 of `e2e.yml` kept `firefox/export.mp4`.

## Done

The cause is the H.264 configuration record that Firefox's `VideoEncoder` returned. Its avcC was `0164002803 01 001a 67 67640028…`: the SPS carries a stray leading `0x67` byte, and the two reserved-bit bytes are `0x03` and `0x01`. `ffprobe` on that file reported `sps_id 1 out of range`. The first key sample carries its own SPS (25 bytes, `67640028…`) and PPS, and `ffprobe` on those in-band units read 1920 by 1080. The `tkhd` and `avc1` boxes already said 1920 by 1080.

`avcDecoderConfig()` in `packages/svgif-export/src/mp4.ts` builds the avcC from the first key sample's SPS and PPS when that sample carries both, with the reserved bits set and the 4:2:0, 8-bit extension for High profiles. Without in-band parameter sets the encoder's record is used as before, which is Chromium's case. Three tests use the real Firefox bytes. The Firefox file rewritten with the rebuilt record read 1920 by 1080 in `ffprobe` and decoded with `ffmpeg`. The Chromium `export-mp4` scenario still passes locally. `mp4.ts` line coverage is 97.78%.
