# Handoff H-352

## State

The fleet coordinator asked for this on 2026-11-24. The owner has new deny terms to add. A secret cannot be read back, and no copy of the current `SVGIF_DENY_TERMS` value exists, so the new terms cannot be merged into that secret.

## Done

- **The two scans:** `scripts/ci/public_surface.py` and `scripts/ci/check_published_artifacts.py` take their forbidden literals from `SVGIF_DENY_TERMS`, `SVGIF_DENY_TERMS_EXTRA` and `SVGIF_DENY_NAMES`.
  - The mask step, the file and message scan, and the artifact scan all use that union.
  - `SVGIF_DENY_TERMS_EXTRA` is optional. Unset or empty, it adds nothing and raises no warning.
  - `SVGIF_DENY_TERMS` stays the required, fail-closed list. `EXTRA` alone does not satisfy it.
  - Both self-tests cover these cases.
- **`.github/workflows/ci.yml`:** the four steps that already receive `SVGIF_DENY_TERMS` also receive `SVGIF_DENY_TERMS_EXTRA`. The required checks do not change.
- **[[sot:svgif/sensitive-content]] item 3:** describes the extra list.

Measured with `bash scripts/ci/public-surface.sh` and `SVGIF_REQUIRE_DENY_TERMS=true`:

| `SVGIF_DENY_TERMS` | `SVGIF_DENY_TERMS_EXTRA` | Result |
| --- | --- | --- |
| a term not in the tree | unset | exit 0 |
| a term not in the tree | a word that a tracked file contains | exit 1, the file is named and the term is not printed |
| a term not in the tree | empty | exit 0 |
| empty | a term not in the tree | exit 1, `SVGIF_DENY_TERMS is not set` |

Both self-tests pass. `actionlint` and `zizmor --offline` report nothing on `ci.yml`, and `spec check` is green.
